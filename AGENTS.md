# ORIVOIR project instructions

Start with the [handoff](docs/handoff.md): where the build stands, the next task, what's waiting on Dot, and how to verify work. Update it in the same pull request whenever status changes, and keep it public-safe.

Read the [living PRD](docs/prd.md) for agreed product behavior and the [user stories](docs/user-stories.md) for acceptance criteria by ID. When an agreed decision changes, update the PRD, the affected stories, and any guide that uses them in the same change. Link to each story by its stable ID.

For build order, milestone scope, open decisions and the definition of done, follow the [implementation plan](docs/implementation-plan.md). Keep its story traceability table current when a story's milestone or status changes.

For the Venture creation wizard and the four MVP roles, follow [Venture launch](docs/venture-launch.md). Update that document when an agreed launch decision changes.

For Crew selection, personal SMS and email invitations, account-free responses, and Date Lock-In notifications, follow [Crew invitations](docs/crew-invitations.md). It includes the data contract, delivery and retry rules, acceptance scenarios, and source references with licenses.
